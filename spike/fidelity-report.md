# Kanwas Local-First — Markdown Fidelity Report (Step 0 spike)

_Generated by `spike/scripts/fidelity.ts` over 18 real markdown files._

Each file is run **md → BlockNote blocks → Yjs `XmlFragment` → md** through the exact
shared conversion code the product uses on save/load
(`ContentConverter.updateFragmentFromMarkdown` on write; `fragmentToMarkdown` on read,
which applies `shared/src/workspace/markdown-normalization.ts`).

## Verdict

**Tier 1 (stock BlockNote lossy exporter + `markdown-normalization.ts`) is sufficient for v1.**
No content was ever lost across the 18-file corpus: heading levels+text (all preserved),
fenced-code bodies (all preserved), link targets (all preserved), and table rows (all preserved).
15/18 files round-trip with **cosmetic reflow only** — bullet `-`→`*`, soft-wrap→`\`
hard-break, table-cell repadding, tight/loose-list and blank-line normalization, emphasis-marker
and thematic-break restyling, `&#x20;` space entities. None of these change rendered meaning.

Two real (but cheap, well-understood) issues surfaced — **neither needs a new serializer or
durable exact-source blocks:**

1. **YAML frontmatter is reinterpreted as body** (14/14 frontmatter files). A leading `---`
   fence is parsed as markdown: the opening `---` becomes a thematic break and the closing `---`
   turns the preceding `description:` line into a **setext H2 heading**. All text survives, but the
   frontmatter renders as visible, mangled body and no longer round-trips as frontmatter. This is
   exactly tolaria's "frontmatter never enters the editor" case; fix = **split frontmatter off
   before conversion and re-prepend on save** (small, isolated).
2. **Ambiguous blockquote / nested-list paragraph boundaries get restructured** (3/18 files:
   `decision-log.md`, `risk-register.md`, `bluf.md`).
   Empty `>` separators inside a blockquote are dropped (two quote paragraphs merge), and a
   lazy-continuation paragraph nested under a list item is promoted to a list item. Text is fully
   preserved; only paragraph/list structure shifts. Low severity under folder-as-truth.

**Recommendation:** ship **Tier 1 + a frontmatter split-guard**. A tolaria-style direct serializer
(with a fidelity flag) would additionally tidy the cosmetic reflow and fix issue #2, but is not
required for correctness — schedule it only if users who hand-tune markdown complain. **Tier 3
durable exact-source blocks are unnecessary:** no fenced/code/table content was corrupted.

**Classification.** _cosmetic-reflow_ = the meaningful text-line sequence is identical after
normalizing the cosmetic classes listed in the verdict, AND heading levels+text, fenced-code
bodies, link targets and table row counts are all preserved. _content-touching_ = the text-line
sequence still differs (here: structural blockquote/list paragraph regrouping). Frontmatter
integrity is tracked as a separate column because the mangling preserves text (so the line
check reads it as cosmetic) while changing how it renders.
